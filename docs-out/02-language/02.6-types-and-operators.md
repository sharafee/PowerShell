# Types and operators

> STATIC-ONLY — behavior not run-verified. `FACT-SRC` unless marked. Detail documents: [OPERATOR-TABLE.md](OPERATOR-TABLE.md) (CF-OP-001), [CONVERSION-RULES.md](CONVERSION-RULES.md) (CF-CNV-001). Binder mechanics: [BINDER-CATALOG.md](BINDER-CATALOG.md).

## 1. Purpose and scope [SPEC]

How values behave in expressions: the value model (`$null`, `AutomationNull`, `PSObject` wrappers, numeric types), arithmetic and promotion, comparison, truthiness, string handling, collection enumeration ("unrolling"), and the regex-style operators with `$Matches`. This is the semantic core a new interpreter must reproduce to give identical results.

## 3. Responsibilities and non-responsibilities

Value semantics of operators and enumeration. Not responsible for syntax (parser), output formatting (T36), member access (ETS, T35).

## 4. Key types and contracts [IMPL]

- **`$null`** is a real null reference. **`AutomationNull.Value`** is a distinct "no value" object: a pipeline or statement that produced nothing evaluates to it; it enumerates as an empty sequence, writes nothing to the pipe, and converts to `$null` when stored.
- **`PSObject`** wraps any .NET object to carry extra (ETS) members; most operations call `PSObject.Base` first, and binders defer to a PSObject-aware path when an operand is a wrapper with a different base object.
- Numeric type order for arithmetic is the `TypeCode` order (`byte`/`sbyte`/`int16`/`uint16` < `int32` < `uint32` < `int64` < `uint64` < `single`/`double` < `decimal`), see [OPERATOR-TABLE.md](OPERATOR-TABLE.md) and `BinaryNumericOp`.

## 5. Data model

Value kinds the operators distinguish: null, string, char, bool, numeric (11 CLR types + `BigInteger`), enum, collection (array, `IEnumerable`, `IList`), dictionary (`IDictionary`/`Hashtable`), `ScriptBlock`, `PSObject`, other objects (with optional `op_*` operators).

## 6. Control flow

Operator evaluation: dynamic binding site → rule chosen from the runtime types of the operands (cached per site) → helper call. Rules are described per operator in [OPERATOR-TABLE.md](OPERATOR-TABLE.md).

## 7. Algorithms

### 7.1 Enumeration and output unrolling (CF-PIP-001)

<!--CF:CF-PIP-001-->**Output unrolling and enumeration rules.** A value is *enumerated* (treated as a sequence) when, after unwrapping `PSObject`: it is `AutomationNull` (empty sequence), an array, a `DataTable` (its rows), a COM enumerable, any other `IEnumerable` that is not a string, `IDictionary` or `XmlNode` (the generic `IEnumerable<T>` enumerator is preferred), or an `IEnumerator`; `null`, strings, dictionaries (hashtables), `XmlNode` and all other objects are **not** enumerated and are single values. When a statement writes its value to the output pipe: `AutomationNull` writes nothing; a non-enumerable value is written as one object (mutable value types are copied first); an enumerable value is **unrolled exactly one level**: each element is written separately (elements that are themselves collections stay whole), and an enumerator is disposed afterwards if the engine created it.<!--/CF-->

Evidence: src/System.Management.Automation/engine/runtime/Binding/Binders.cs::PSEnumerableBinder.FallbackConvert@L580-L693, src/System.Management.Automation/engine/runtime/Binding/Binders.cs::PSPipeWriterBinder@L841-L926, src/System.Management.Automation/engine/runtime/Operations/MiscOps.cs::EnumerableOps.WriteEnumerableToPipe@L3623-L3640, src/System.Management.Automation/engine/LanguagePrimitives.cs::LanguagePrimitives.CalculateGetEnumerable@L527-L543, [02.5-compiler-and-engine.md](02.5-compiler-and-engine.md) §6.5 (capture), src/System.Management.Automation/engine/runtime/Operations/MiscOps.cs::PipelineOps@L29-L889. Capturing output in `$x = …`, `@(…)` or `$(…)` collects what was written to a temporary pipe (`PipelineOps.PipelineResult`); the usual result shapes (no output → `$null`, one object → that object, several → `object[]`; `@(…)` always an array) were **not** read in `PipelineResult` and are `UNVERIFIED` (VB-019).

### 7.2 Arithmetic and promotion

For numeric operands the wider `TypeCode` selects the implementation class (`IntOps`, `UIntOps`, `LongOps`, `ULongOps`, `DecimalOps`, `DoubleOps`); `int` addition, subtraction and multiplication that overflow return a `double`; `int` division returns an `int` if exact and a `double` otherwise; division or remainder by zero raises a `RuntimeException`; a signed negative operand mixed with `uint`/`ulong` falls to `long`/`decimal` (with double fallback on overflow). A string operand of a numeric operator is converted with the language number scanner (CF-LEX-002). Evidence: src/System.Management.Automation/engine/runtime/Operations/NumericOps.cs::IntOps@L15-L129, src/System.Management.Automation/engine/runtime/Binding/Binders.cs::PSBinaryOperationBinder.BinaryNumericOp@L2384-L2539.

### 7.3 Comparison

Detailed in [OPERATOR-TABLE.md](OPERATOR-TABLE.md) and [CONVERSION-RULES.md](CONVERSION-RULES.md) §7.6: left operand drives; strings compare with the culture comparer (plain and `i` operators ignore case, `c` operators do not); a collection on the left makes comparison operators **filter** instead of returning a bool; `$null` rules (`$null -eq x` only for `$null`; `x -eq $null` false for non-null scalars).

### 7.4 Regex and wildcard operators

`-match`/`-notmatch`: regex (culture-aware options by case flag); scalar left operand sets `$Matches` (hashtable with case-insensitive keys, numeric group names as integer keys); array left operand returns the matching elements. `-like`/`-notlike`: wildcard pattern; array left operand filters. `-replace`: regex replace with a replacement string or a script block evaluator. `-split`/`-join`: described in the table. Regex objects are cached by (options, pattern) with a cap of 1,000 per option set that clears the set when exceeded. Evidence: src/System.Management.Automation/engine/lang/parserutils.cs::ParserOps@L232-L1624 (notes W2-W5).

### 7.5 Strings

String `+` appends the right operand's string form; `*` repeats; indexing, slicing and `-f` follow the table; string comparison uses the culture of the operation (invariant for conversions and the operators unless a culture is passed). Double-quoted expansion builds the string with `-f`-style formatting of nested expressions each converted with the `PSToStringBinder` (enumerables joined with `$OFS`, default space).

## 8. Observable behavior [SPEC]

Read from source: `2147483647 + 1` gives a `double`; `7 / 2` gives `3.5` and `6 / 2` gives `3` (an `int`); `"a" * 3` is `"aaa"`; `@(1,2) + 3` is a 3-element array; `1,2 -eq 2` returns `2` (filter) not `$true`; `$null -eq $null` is `$true`; `"abc" -like "a*"` is `$true`; `[bool]@(0)` is `$false`. No golden sample: STATIC-ONLY. Tests: `test/powershell/Language/Operators/` (`data/tests.json`; mapping `UNVERIFIED`).

## 9. Error handling and edge cases

`PSInvalidCastException` for failed conversions; `RuntimeException` wrapping `DivideByZeroException`; "cannot apply operator" errors (`op_*` not found) from `CallImplicitOp`; `AddHashTableToNonHashTable`; regex errors wrapped as `InvalidRegularExpression`; comparison failures as `PSArgumentException`.

## 10. Concurrency and threading

Binder rules and conversion caches are shared across threads (concurrent dictionaries/locks); `$Matches` is a scope variable (per runspace).

## 11. Extension points and customization hooks

User types can define `op_Addition`, `op_Subtraction`, `op_Multiply`, `op_Division`, `op_Modulus` (looked up via `CallImplicitOp`, preferring the left operand's type unless it is primitive or null), `IComparable`, `Parse`, and type converters.

## 12. Dependencies

Inbound: compiled code (binders), parameter binding, `Where-Object`/`Sort-Object` (comparison). Outbound: ETS (`PSObject`), conversion layer, regex engine, culture info.

## 13. Performance notes

Binder rules are cached per call site by operand types; integer arithmetic avoids boxing in typed fast paths (`IntOps` returns boxed objects only because results may switch type).

## 14. Security considerations (mandatory)

User-defined operator and conversion methods run code during an innocent-looking expression; Constrained Language Mode restricts which types participate (conversion gate, binder language checks). Regex cache and `-split`/`-replace` with attacker-controlled patterns can cause catastrophic backtracking (no timeout was found in `NewRegex`, `UNVERIFIED`).

## 15. Enterprise considerations

`string * n` and array repetition are capped at 1,024 only in RestrictedLanguage mode (data sections); a negative string repeat count throws `ArgumentOutOfRangeException`; no cap outside data sections was found; `Range` allocates the full array.

## 17. Design decisions and trade-offs

| Decision | Label | Consequence |
|---|---|---|
| left-operand-driven typing | `FACT-SRC` | asymmetric results (`1+"2"` vs `"1"+2`); easy to implement, surprising |
| arithmetic overflow promotes to double | `FACT-SRC` | no integer overflow exceptions in scripts |
| comparison operators filter collections | `FACT-SRC` | concise filtering, but `if ($a -eq 1)` with arrays is truthy on non-empty result |
| output unrolls one level | `FACT-SRC` | pipelines stream elements; nested arrays flatten one level only |
