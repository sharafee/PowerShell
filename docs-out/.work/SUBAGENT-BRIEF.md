## 2. Operating rules (non-negotiable)

1. **Evidence only.** Every non-trivial statement cites evidence in the format `src/<Project>/<path>.cs::Type.Member@L120-L188` (repo-relative path, type or Type.Member, line range). Lines are 1-based and must be real: open the file and check. `E1` = pinned source. Comments/XML docs are evidence of intent only. Never trust your memory of PowerShell; every file name, type, number or claim in the study prompt is a hint to verify. If a hint is wrong, say so in your report.
2. **Labels.** Each factual statement carries exactly one label (inline for non-trivial claims, or per block when a block shares one): `FACT-SRC` (read in source), `INFERENCE` (why/intent/not directly stated), `EXTERNAL` (docs/.NET facts, cross-check only), `UNVERIFIED` (not read; goes to the backlog). Modifiers: `APPROX` (regex/heuristic extraction), `GENERATED` (rendered from data), `VERSION-MISMATCH` (n/a here). Tag every section `[SPEC]`, `[IMPL]` or `[LESSON]` (SPEC = observable language/runtime behavior independent of how PowerShell implements it; IMPL = how this source implements it; LESSON = design lesson for the new shell). Tags and labels are orthogonal.
3. **Verdicts.** The only lesson vocabulary: `REPLICATE` (reproduce observable behavior and essential mechanism; default for CORE), `ADAPT` (same observable behavior, different mechanism; say why), `REDESIGN` (observable behavior intentionally different = deviation *proposal*), `AVOID` (omit; say what replaces it = deviation *proposal*). Every `REDESIGN`/`AVOID` names exactly one deviation ID `DEV-<AREA>-<NNN>` that you propose in `docs-out/.work/cf/<task-id>.json` under `"deviations"` (fields: id, baseline_behavior, proposed_behavior, benefit, compatibility_cost, affected_cfs). Until approved the baseline stays `REPLICATE`. You may only write status `PROPOSED`.
4. **Counts and constants come from data, never from memory or hand counting.** Registered numbers are in `docs-out/data/numbers.json`; embed them as `<!--N:KEY-->value<!--/N-->` (run `python3 docs-out/tools/numbers.py render` to fill, `lint` to check). For a count you need that is not registered, propose it in `docs-out/.work/numbers-proposals/<task-id>.json` as `[{"key":"UPPER_SNAKE","cmd":"<shell command that prints the number>","dataset":"<file>","label":"APPROX","notes":"..."}]` (the coordinator merges it) and embed `<!--N:KEY-->?<!--/N-->` in the text. Source constants (thresholds, limits, defaults) must be quoted with their constant name and evidence; if a constant is critical, propose a CF (below).
5. **Canonical facts (SSOT).** A fact that two documents need has exactly one statement in `data/canonical-facts.json` (`CF-<AREA>-<NNN>`) and one owner document. You may only *propose* CFs/statements for the CF IDs your task owns in `docs-out/.work/cf/<task-id>.json` (`{"cfs":[{"id","subject","statement","label","evidence":[...],"owner","status":"open|closed"}], "deviations":[...]}`). `closed` means the statement is fully read from source (no `UNVERIFIED`); otherwise `open`.
